# Product Requirements Document (PRD) - Stage 0: Анонимный таймер-цикл "1234"

## 1. Stage 0 Overview (Суть этапа)

**ВАЖНО:** В момент выпуска v1.0.0 этап вышел за рамки исходного Stage 0 и включил функционал до Stage 11. Ниже указан фактически реализованный продукт.

1234 Timer реализует 4 фазы с психологической механикой удержания:
- **THINKING (60s)** → **PREP (120s)** → **STRIKE (180s)** → **ПЕРЕЗАГРУЗКА (60-240s случайно)**

Фаза ПЕРЕЗАГРУЗКА имеет скрытый таймер (пульсирующая анимация) и автоматический перезапуск цикла.

---

## 2. The Core User Flow (Пользовательский путь)

### Стандартный цикл:
1. Пользователь видит "ФАЗА 1. THINKING" и "01:00"
2. Нажимает **СТАРТ** → таймер работает
3. По окончании THINKING: оверлей "ЦЕЛЬ НАЙДЕНА?" (ДА/НЕТ)
4. ДА → переход к PREP (автоматический запуск)
5. НЕТ → сброс к THINKING (автоматический запуск нового цикла)
6. После PREP → STRIKE (автоматически)
7. После STRIKE: система входит в режим ожидания:
   - в базовом поведении: пользователь выбирает "⚡ ИНЕРЦИЯ" или "🧠 ОТДЫХ" (30 сек таймаут);
   - в версии v1.2: экран выбора "ИНЕРЦИЯ/ОТДЫХ" отсутствует — после STRIKE автоматически запускается INERTIA.
8. ИНЕРЦИЯ: режим потока с таймером секунд (в v1.2 также содержит внутренние pulse/confirm-логику)
9. ОТДЫХ: случайная длительность (1-4 мин), пульсация вместо таймера
10. После ОТДЫХА: автоматический переход к THINKING (новый цикл)

### Управление:
- **СТАРТ/ПАУЗА (toggle):** запуск/пауза таймера
- **СБРОС:** полный сброс к начальному состоянию
- **ИНЕРЦИЯ:** после STRIKE (только Premium)
- **ОТДЫХ:** после STRIKE (все пользователи)

## Version 1.1 - Upgrade: Meta Time Scaling (Global Time Warp)

### 1. Upgrade Overview & Business Goals
Добавляем глобальный ползунок “мета-масштабирования времени”, который позволяет управлять темпом полного цикла работы (всеми фазами в заданной последовательности) без изменения порядка фаз. Цель — повысить качество выполнения за счет управляемого “разгона/погружения” и снижения риска “залипания” в одной фазе.

### 2. Impact on Existing System (Влияние на текущую систему)
- **Затронутые старые модули:** таймер-цикл “1234” (длительности фаз THINKING → PREP → STRIKE → ПЕРЕЗАГРУЗКА), визуализация таймера/прогресса, логика авто-переходов по окончанию фаз.
- **Изменения в поведении:** длительности фаз теперь динамически масштабируются параметром Meta Time Scaling. При этом порядок фаз и условия переходов сохраняются (THINKING → PREP → STRIKE → ПЕРЕЗАГРУЗКА не меняются).

### 3. New Features & Acceptance Criteria
**Feature 1.1.1: Global Meta Time Scaling Slider (Time Warp)**
- Описание: в UI появляется глобальный ползунок масштаба времени, который влияет на длительности всех интервалов/фаз во всех последовательностях.
- AC1: Пользователь может изменить масштаб времени, и значение влияет на тайминг фаз **без смены порядка фаз** (THINKING → PREP → STRIKE → ПЕРЕЗАГРУЗКА).
- AC2: Изменение масштаба во время RUNNING приводит к корректному пересчету “момента окончания фазы” так, чтобы авто-переходы продолжали срабатывать **ровно один раз на завершение каждой фазы** (guard от повторного триггера на одном и том же тике).
- AC3: При низком масштабе цикл работает быстрее (фазы короче), при высоком — медленнее (фазы длиннее).
- AC4: Логика исключает зависание на одной фазе: окончания фаз и авто-переходы продолжают происходить по корректно масштабированному таймеру (не требуется ручной сброс для продолжения цикла).

**Feature 1.1.2: Distinction от Chaos Protocol**
- Описание: Meta Time Scaling — контролируемый параметр, а не случайная длительность.
- AC1: В отличие от Chaos Protocol, Meta Time Scaling не вводит случайность длительности фаз; изменение темпа определяется значением ползунка.
- AC2: Chaos Protocol продолжает работать как есть для фаз, где он задуман, а Meta Time Scaling лишь масштабирует темп.

### 4. New Success Metrics (Метрики успеха)
- Увеличение доли пользователей, которые проходят полный цикл без ручного “СБРОС” при изменении масштаба времени.
- Рост повторных запусков цикла (retention) в сессиях после изменения Meta Time Scaling.
- Снижение частоты “залипания”/ошибочных сценариев авто-переходов (по логам таймера и событий фаз).

## Version 1.2 - Upgrade: Deep Flow Inertia Controller (Auto after Phase 3)

### 1. Upgrade Overview & Business Goals
Цель апгрейда — убрать лишнее ветвление после завершения фазы 3 (“Уничтожай”) и перевести пользователя в режим **INERTIA** автоматически, без дополнительного запроса инерции/отдыха. Это снижает когнитивную нагрузку и поддерживает удержание в потоке за счет ритма + мягкого уведомляющего сигнала bypass-app\bypass-apk\assets\sounds\ignite.mp3.

### 2. Impact on Existing System (Влияние на текущую систему)
- **Затронутые старые модули:** state machine цикла “1234”, UI инерции, аудио bypass-app\bypass-apk\assets\sounds\ignite.mp3 , переход в режим отдыха.
- **Изменения в поведении (Behavior Change):**
  - После фазы 3 вместо выбора “⚡ ИНЕРЦИЯ / 🧠 ОТДЫХ” система автоматически переходит в **INERTIA**.
  - В INERTIA добавляется:
    - случайный интервал pulse **3–6 минут**;
    - единственная кнопка **EXIT**;
    - лимит бездействия: находиться без ответа можно только **6 циклов**;
    - на 6-м цикле появляется вопрос, требующий ответа **YES в течение 30 секунд**; иначе происходит авто-выход в **ОТДЫХ**.

### 3. New Features & Acceptance Criteria
**Feature 1.2.1: Auto-enter INERTIA сразу после Phase 3**
- Описание: по окончании STRIKE (фаза 3) происходит автоматический переход в INERTIA.
- AC1: INERTIA начинается без пользовательского выбора (нет экрана выбора “инерция/отдых”) с сигналом bypass-app\bypass-apk\assets\sounds\ignite.mp3.
- AC2: Автопереход выполняется ровно один раз на конкретное завершение STRIKE (guard по идентичному завершению/таймштампу, чтобы после рестарта не было повторного входа).

**Feature 1.2.2: Deep Flow Pulse 3–6 минут (не отвлекающий)**
- Описание: в режиме INERTIA каждые **рандомные 3–6 минут** подается тот же тип звукового сигнала, но **не сильно отвлекающий** bypass-app\bypass-apk\assets\sounds\ignite.mp3.
- AC1: Интервал между сигналами лежит в диапазоне 3–6 минут.
- AC2: Сигнал воспроизводится только пока активен режим INERTIA.
- AC3: Поведенческий эффект сигнала — мягкое подтверждение пользователю, что он всё еще находится в INERTIA.

**Feature 1.2.3: INERTIA UI Lock и только одна кнопка EXIT**
- Описание: в режиме INERTIA пользователь видит один основной элемент управления — кнопку **EXIT**.
- AC1: В INERTIA отсутствуют другие кнопки/действия пользователя (кроме EXIT).
- AC2: Поведение UI соответствует концепции “нет запроса инерции/отдыха, только выход”.

**Feature 1.2.4: Лимит бездействия INERTIA и 30-секундный confirm**
- Описание: при отсутствии действий пользователь может находиться в INERTIA **только 6 циклов** (счётчик виден в уведомлении «Цикл X/6»).
- AC1: После достижения лимита (6 циклов без действий) появляется оверлей (всё ещё в режиме INERTIA): "MAX FLOW REACHED. CONTINUE?" + звук `beep.mp3` ровно один раз.
- AC2: У пользователя есть **30 секунд**, чтобы ответить: **YES** (продолжить, счётчик сбрасывается) или **NO** (немедленный выход в ОТДЫХ).
- AC3: Если ответа не последовало в течение 30 секунд — система автоматически выходит в **ОТДЫХ**.

**Feature 1.2.5: Выход из INERTIA переводит в стандартный Recovery/Rest flow**
- Описание: нажатие EXIT завершает режим INERTIA и запускает стандартный переход дальше как “и раньше”.
- AC1: EXIT приводит к выходу из цикла INERTIA и переходу в **ОТДЫХ**.
- AC2: Дальнейшая логика после ОТДЫХА работает как в текущей системе (в цель / либо цель создана, либо нет, затем дальнейшие шаги по текущим правилам).

### 4. New Success Metrics (Метрики успеха)
- Рост доли сессий, где после фазы 3 пользователь автоматически входит в INERTIA без ручного выбора (conversion в инерцию без вмешательства).
- Снижение количества действий пользователя в момент после фазы 3 (уменьшение “ручных переключений”).
- Доля авто-выходов из INERTIA по таймауту “нет ответа в 30 секунд” (контроль отсутствия деградации удержания).
- Субъективный/поведенческий сигнал “не отвлекает” (меньше уходов/остановок в INERTIA, чем при прежнем ветвлении).

> 🛑 **Deviation (отклонение от Stage 11 Paywall):** в V1.2 авто-вход в INERTIA после STRIKE выполняется **для всех пользователей**, без проверки Premium (см. TECH_SPEC.md → As-Built Deviations V1.1/V1.2, п.2). Лимит 3 цикла/день для Free и Premium-статус сохраняются для остальной логики, но гейт «Инерция только для Premium» в авто-режиме V1.2 не применяется.

## Version 1.3 - Upgrade: Auto-Start Scheduler (“THE HIT-LIST”)

### 1. Upgrade Overview & Business Goals
Добавляем планировщик “THE HIT-LIST”, который автоматически инициирует цикл продуктивности **в заданное пользователем время** без ручного нажатия кнопки “СТАРТ”.
- **Бизнес-цель:** повысить регулярность использования техники (retention) и снизить “трение старта” перед началом цикла.
- **Пользовательская ценность:** пользователь выбирает время один раз (несколько слотов), а система включает байпас-режим по расписанию.

### 2. Impact on Existing System (Влияние на текущую систему)
- **Затронутые старые модули:**
  - таймер-цикл “1234” (`TimerProvider`): старт фазы 0 и дальнейшие автопереходы;
  - оверлей “ЦЕЛЬ НАЙДЕНА?” (ожидание ответа после THINKING);
  - Android foreground service (существующая реализация для фонового присутствия).
- **Изменения в поведении (Behavior Change):**
  - появляется дополнительный путь старта цикла: **авто-старт по расписанию**;
  - при конфликте с активной работой цикла автозапуск **не выполняется**.

### 3. New Features & Acceptance Criteria

**Feature 1.3.1: Отдельный экран планировщика “THE HIT-LIST”**
- Описание: новый экран, где пользователь добавляет и управляет множеством слотов расписания.
- AC1: Экран поддерживает до **10** слотов.
- AC2: У каждого слота есть переключатель включения/выключения.
- AC3: Время слота выбирается через **ползунки HH:mm** (час/минута).
- AC4: Пользователь может добавить новый слот и удалить существующий.
- AC5: Расписание считается активным, если включен **хотя бы один слот**.

**Feature 1.3.2: Авто-старт по расписанию (каждый день)**
- Описание: каждый включенный слот триггерит авто-старт **ежедневно** в выбранное HH:mm.
- AC1: В момент срабатывания инициируется цикл в состоянии **фаза 0 → ожидание подтверждения цели** (соответствует базовой логике старта для “ЦЕЛЬ?”).
- AC2: Автозапуск повторяется каждый день в то же время, пока слот включен.

**Feature 1.3.3: Анти-дубликаты и конфликтующие слоты**
- Описание: если несколько слотов запланированы на одно и то же время, система не допускает повторный “мешающий” запуск.
- AC1: Для одного временного срабатывания выполняется запуск **только одного** слота (остальные игнорируются).
- AC2: Повторные триггеры в одну и ту же минуту не приводят к повторному старту.

**Feature 1.3.4: Запрет авто-старта при активной работе приложения**
- Описание: если пользователь уже работает в цикле, автозапуск должен быть отключен.
- AC1: Если `timerProvider.isRunning == true`, авто-старт не инициируется (и не перезапускает цикл).

**Feature 1.3.5: Идемпотентность “один раз на окно”**
- Описание: система должна гарантировать отсутствие дублей из-за пересоздания расписания, перезапусков приложения или повторного срабатывания будильников.
- AC1: Для каждой минуты используется идемпотентный ключ “дата+HH:mm” (windowKey). Если windowKey уже был выполнен — повторный запуск в ту же минуту не выполняется.
- AC2: При конфликте нескольких слотов на одно HH:mm запуск выполняется для одного детерминированного winner-слота (по stable slotOrdinal), остальные no-op.

### 4. New Success Metrics (Метрики успеха)
- Рост доли дней, когда пользователь получает старт цикла без ручного нажатия “СТАРТ”.
- Снижение количества сессий с “пропуском старта” (когда пользователь планировал время, но не начал цикл).
- Уменьшение количества инцидентов с дублями стартов (измеряется по логам triggerId/slotId).
  - Снижение конфликтов с активным циклом (auto-start при `isRunning=true` должен быть = 0).

### 4.1 🛑 As-Built Deviations (V1.3 / HIT-LIST)
> Синхронизировано с реальным кодом (см. TECH_SPEC.md → As-Built Deviations V1.3).

1. **Sustained звуковой сигнал при авто-старте.** Изначальный blueprint Stage 7 (§2) требовал «НИКАКИХ дополнительных сигналов … никаких beep/месседжей». По факту (2026-07-15, фидбек) при срабатывании расписания играет выделенный непрерывный `beep.mp3` длительностью **≥ 30 секунд** (`AudioService.playScheduleAlarm()`), останавливаемый на СБРОС/подтверждение цели. «Тихий» старт не реализован.
2. **Механизм триггера — in-app poll, не будильник.** AC5 blueprint (права «как у будильника», авто-старт после выгрузки/ребута) **не выполнен**. Реализован внутриприложный poll каждые 15с поверх foreground service; без Android `AlarmManager`/boot-receiver. Авто-старт работает только пока жив процесс приложения.
3. **Однократный режим «Repeat daily = off» не реализован.** Все включённые слоты повторяются ежедневно; переключателя однократного запуска нет (только `enabled`).

### 5. Testing & Validation (критические проверки)
- Проверить, что расписание реально триггерит запуск ежедневно в выбранное HH:mm.
- Проверить, что при `timerProvider.isRunning == true` запуск не происходит.
- Проверить конфликтующие слоты на одинаковое время: запускается только один слот.
- Проверить идемпотентность при повторных обновлениях/пересоздании расписания.
- Проверить UX: экран планировщика корректно сохраняет/отображает включенные слоты после перезапуска приложения.
